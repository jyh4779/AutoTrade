# 감시 중복 방지 수정

## 구현

- 저장소 경로와 역할을 키로 Windows 전역 mutex를 사용한다. 계정이 다른 Windows 세션에서도 동일 프로젝트의 감시·스케줄러 동시 실행을 차단한다. 접근 불가이면 실행을 허용하지 않는다.
- 감시 잠금은 트레이더 생성 전에 획득한다. 잠금 충돌은 종료 코드 75와 별도 이벤트로 구분한다.
- 스케줄러는 시작 이벤트의 PID·생성 시각·프로세스 이름을 대조해 기존 계측 감시를 조회한다. 기존 실행이 있으면 새 감시를 실행하지 않고 상태를 기록한다. 발견 실패도 신규 실행을 보류한다.
- 스케줄러 정상 종료·KeyboardInterrupt·초기화 실패 경로에서 finally로 소유 자식 트리를 정리한다. 장 종료 시에도 단일 런처만 종료하지 않고 트리를 확인한다. 이 정리는 매도를 요청하지 않는다.
- 감사는 현재 중복 수, 최근 활동 지연, 실행 중인 구버전을 각각 검사한다. 이미 종료된 PID나 재사용된 PID는 생성 시각 대조로 제외한다.

## 검증 및 한계

Windows 프로세스·잠금 테스트와 기존 회귀 검증을 수행했다. 실제 주문은 보내지 않았다. 신규 감사는 기존 감시 2개를 FAIL로 검출했다.

Windows의 terminate는 강제 종료이므로 처리 중 요청의 완료를 보장하지 않는다. 원장에 남은 미해결 주문은 재기동 후 조회로 해소한다. 스케줄러 자체의 강제 종료에서는 finally가 실행되지 않을 수 있으며, 이 경우 새 실행의 잠금·기존 프로세스 발견으로 중복을 방지한다.

새 잠금은 구버전 감시에 소급 적용되지 않는다. 기존 잔존 프로세스 정리와 서비스 재시작은 관리자 권한이 필요하며 이번 코드 검증으로 실제 재시작 성공을 주장하지 않는다. NSSM 설정은 변경하지 않았고 실제 서비스 반복 재시작 검증은 운영 적용 시 남아 있다.

발견은 계측된 시작 이벤트에 기반한다. 이벤트 없이 실행된 구버전 프로세스는 이 조회로 발견할 수 없다. 현재 잠금은 프로젝트의 주식 역할 전체를 제한하는 보수적인 범위이며, 복수 계정 실행 도입 시 검증된 계정 별칭으로 범위를 확장한다.
