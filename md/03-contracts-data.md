# 공통 계약과 데이터 저장

이 문서의 표준 계약은 목표이며 현재 SQLite 스키마와 다르다. 기존 장부에 바로 적용하지 말고 [전환 절차](07-migration.md)를 따른다.

| 자료형 | 필수 정보 |
|---|---|
| Instrument | 자산군, 거래소, 상품 코드, 기준·결제 통화, 상품 유형, 가격·수량 단위, 최소 주문 조건, 규격 확인 시각 |
| Quote / Bar | 상품, 공급자 시각(없으면 null), 수신 시각, 가격·거래량, 봉 구간, 확정 여부, 출처 |
| Signal | 전략 ID·버전, 평가 시각, 입력 스냅샷, 구성 점수, 진입 자격, 제외 사유 |
| OrderIntent | 계정 별칭, 전략, 상품, 방향, 주문 유형, 수량 또는 금액, 고유 식별자 |
| Fill | 거래소 주문·체결 ID, 수량, 금액, 실제 수수료와 통화, 체결·수신 시각 |
| AccountSnapshot | 계정 별칭, 사용 가능·주문 잠금 잔고, 보유 자산, 평가 기준 시각·통화 |

## 수량과 식별

- 주문 금액·수량·비용은 십진 정밀도로 계산한다. DB 저장은 십진 문자열 또는 명시된 배율의 정수로 설계한다. 부동소수 REAL을 정확한 주문 원장으로 간주하지 않는다.
- 정수 주식 수량은 주식 주문 규격으로 검사한다. 시장가 매수 금액과 매도 수량은 서로 다른 주문 입력이다.
- 상품은 코드만으로 식별하지 않는다. 자산군·거래소·상품 코드의 조합을 사용한다.
- 주문 의도는 시장·거래소·계정·전략·신호 식별자를 포함한다. 거래소 제출용 ID는 해당 거래소의 길이·고유성 제약에 맞춰 매핑한다.
- 하루 한 번 매수와 재진입 제한은 시장 전략 정책이다. 공통 주문 ID에 날짜만 넣어 모든 시장에 강제하지 않는다.
- UTC 발생 시각과 KST 보고일을 구분한다. 코인 손실 한도 리셋 시각도 명시하고 재시작으로 리셋하지 않는다.

## 저장 분리

현재 원본: `data/portfolio.db`, `data/audit.db`, `data/pre_analysis_cache_kospi.json` 및 `.meta.json`, `data/strategy_config.json`.

목표: `data/stocks/`와 `data/crypto/<exchange>/` 아래 계정별 장부·캐시·설정을 분리한다. 경로는 실행기가 주입하며 공통 엔진에 `D:\ML`을 고정하지 않는다. 기존 `data/stocks/*.csv`와 이름 충돌을 피하도록 실제 이전 시 하위 경로를 확정한다.

로그 스키마는 공통으로 유지한다. 독립 실행기의 저장 경합을 피할 수 있는 저장소 구성을 선택하고 보고서에서 통합한다. 모든 새 이벤트에 시장·거래소·계정 별칭·전략·실행 모드를 포함한다. 과거 이벤트에 없는 필드를 추정해 채우지 않는다.

잔고 갱신과 체결 원장을 구분한다. 잔고 동기화로 거래 이력을 덮어쓰지 않는다. 통합 손익은 환산 통화·시각·환율 출처를 표시한다.

## 데이터 품질

캐시는 시장, 생성일, 출처, 목록, 내용 해시를 확인한다. 시세 누락, 무거래 봉, 연결 장애는 구분한다. 반복 봉은 구간 키로 갱신하며 완료된 봉과 진행 중인 봉을 혼합해 백테스트하지 않는다. 당시 투자 대상 목록과 제외 사유를 보관해 생존 종목만으로 과거를 평가하지 않는다.
