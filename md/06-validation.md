# 검증과 자체 점검

## 완료 상태

각 변경은 구현 완료, 프로세스 적용 확인, 동작 검증, 성과 검증을 따로 기록한다. 테스트 통과를 실체결 검증이나 수익성 입증으로 표현하지 않는다.

검사 상태는 PASS, FAIL, WARN, UNKNOWN, N/A를 사용한다. 증거 부족은 UNKNOWN, 거래가 없어 해당되지 않는 체결 검사는 N/A다. 이전 실패가 복구되면 원본 실패와 복구 실행을 연결하고 삭제하지 않는다.

## 필요한 테스트

- 구조 이전: 같은 저장 입력에서 주식 점수·배분·차단·청산 판단 일치.
- 주문: 소수·정수 규격, 최소 주문, 금액·수량 구분, 중복 의도, 응답 유실, 부분 체결, 취소 확인, 재시작 대조.
- 데이터: 오래된 캐시·시장 혼입·미확정 봉·중복 봉·누락·계산 불가.
- 격리: 주식·코인 계정·장부·주문 ID 충돌 방지, 한 연결 장애가 다른 실행기를 중단하지 않음.
- 위험: 시장 차단 중 평가 지속 및 신규 주문 0건, 진입 차단 중 청산 가능, 재시작 후 손실 한도 유지.
- 운영: 실제 예약 실행 방식에서 import·환경·종료 코드 확인, 실패 후 복구 이력.

영향에 맞는 테스트만 수행한다. 문서만 수정할 때 실거래 서비스 재시작이나 매매 테스트는 필요하지 않으며 링크·내용·현재/목표 구분을 확인한다.

## 독립 점검

저장된 입력으로 점수를 독립 재계산하고, 거래소 계좌·주문 조회와 로컬 장부를 대조한다. 로그에 정상이라고 쓰였다는 이유만으로 PASS로 판정하지 않는다.

선정 목록의 모든 종목에 평가 결과 또는 제외·실패 사유가 있어야 한다. 시장 필터에는 지표 출처·기준일·관측 시각·임계값·허용 여부를 남긴다. 작업에는 시작·종료·종료 코드·출력 경로를 연결한다.

새 시장 도입 시 이벤트에 시장·거래소·전략 범위가 있는지 검사한다. 시작 로그만으로 프로세스 생존을 추론하지 않는다. 중복 실행·활동 지연 검사는 별도 구현 및 검증한다.

## 연구와 전략 변경

판단 재현과 전체 포트폴리오 백테스트를 구분한다. 비용·슬리피지·거래 불가능 구간·투자 대상 변화·뉴스 가용 시각을 반영하고, 봉 내부 손절·익절 순서가 불명확하면 유리한 순서를 가정하지 않는다.

배점 변경은 기존안과 외부 표본에서 비교하고 수익률·손실폭·회전율·비용·거래 수를 기록한다. 변경안 생성이 실거래 설정 승격을 뜻하지 않는다. 실험 버전·데이터·적용 범위·복구할 설정을 함께 보관한다.
