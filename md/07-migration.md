# 단계별 전환 계획

## 현재 상태 — 2026-09-11

업비트 원화 공개 데이터 연결과 주문 없는 단일 평가 실행기가 추가됐다. [업비트 구현 범위](08-upbit.md)를 참조한다. 코인 인증·실주문·공통 주문 원장은 아직 전환하지 않았다.

운영 모듈 24개의 구현을 새 경로로 이전했다. 기존 경로는 import 시 동일 모듈을 반환하고 직접 실행 시 새 구현으로 연결하는 호환 진입점이다. 서비스 등록 경로와 DB 위치·스키마는 유지한다. 코인 연결·공통 십진 주문 원장은 미구현이다.

공통 관측 기능은 `src/core/observability`, 배분 함수는 `src/core/risk/allocation.py`, 십진 상품·주문 계약은 `src/core/models/contracts.py`, 목표 브로커 인터페이스는 `src/core/ports/broker.py`에 있다. 새 계약은 아직 기존 KIS 주문 원장을 대체하지 않는다.

주식 전용 주문 원장·감사·재현은 `src/markets/stocks`에 남겨 주식 가정이 공통 엔진으로 확산되지 않게 했다. 시세 API와 뉴스 분석을 조립하는 스크리너는 `src/runners/stock_screener.py`, OpenDART 연결은 `src/adapters/dart`에 배치했다. 코인 폴더나 미구현 공통 주문 엔진의 빈 파일은 만들지 않았다.

검증: 기존 및 구조 테스트 38개 통과, 기존 스크립트 CLI와 모듈 CLI 도움말 확인, 컴파일 검사 통과, 오늘 저장 입력 재현 21건이 이전 결과와 일치. 백업은 `data/baselines/20260911_114002_structure`이며 코드와 SQLite backup API로 생성한 장부·감사 DB, 이동 매핑을 포함한다.

상주 서비스는 이 작업에서 재시작하지 않았다. 다음 자식 작업은 호환 진입점에서 새 구현을 읽으며 상주 프로세스의 버전 적용은 재시작 후 별도 확인한다.

주식 운영에는 코스피 제한, 시장 차단 중 평가 지속, 구조화 로그, 캐시 검증, 주문 상태 저장, 독립 점검이 구현돼 있다. 종목 유형 필터, 목표 목록 수 확보, 프로세스 생존·중복 검사, 미매수 손익 추적, 외부 표본 성과 검증은 남아 있다. 과거 테스트 수·실행 결과는 `docs/`의 날짜별 증거를 확인한다.

## 파일 이동 계획

| 기존 위치 | 목표 위치·분리 내용 |
|---|---|
| `src/observability/` | `src/core/observability/` |
| `src/audit/` | 공통 실행은 `core/audit`, 시장별 검사는 해당 정책으로 분리 |
| `src/trading/order_manager.py` | 상태 관리는 `core/execution`, 주식 수량·비용·당일 제한은 stocks/KIS로 분리 |
| `src/trading/strategy_logic.py` | 순수 기본 함수는 core, 주식 거래량·갭·배점은 stocks |
| `src/trading/morning_screener.py` | stocks의 목록·데이터·전략으로 분리 |
| `src/trading/kis_*` | `src/adapters/kis/` |
| `src/main_scheduler.py`, `watchdog.py` | `runners/stocks.py`와 공통 감시 기능, 기존 진입점은 호환 유지 |
| `src/research/` | 공통 재현 실행과 시장별 체결·비용 모델 분리 |
| `src/dashboard/` | reporting의 통합 조회로 점진 전환 |

## 전환 순서

1. 코드·설정·일관된 DB 백업과 기준 입력 확보.
2. 공통 상품·주문·체결 계약, 정밀도·식별자 설계 및 테스트.
3. 주식 정책과 KIS 연결을 추출하고 기존 진입점에서 호출. 이 단계에서 전략 수치는 유지.
4. 공통 주문·감사 엔진 전환. 장부는 버전 있는 마이그레이션과 건수·수량·금액 대조 후 적용.
5. 시장별 실행기·설정·저장 경로 분리. 장애 격리와 복구 검증.
6. 확정된 코인 거래소의 읽기 연결·데이터 저장·주문 없는 평가 구현.
7. 코인 주문 규격·체결·장애 테스트 및 실시간 모의 검증.
8. 검증 결과와 사용자의 실거래 적용 범위를 확인한 뒤 코인 실거래 활성화.

각 단계는 [검증 기준](06-validation.md)을 통과해야 완료로 표시한다. 전체 파일 이동, 전략 변경, 실거래 전환을 한 번에 묶지 않는다.

## 복구 원칙

기존 진입점은 전환 기간에 호환 래퍼로 유지한다. 새·구 실행기가 같은 계정에 동시에 주문하지 않도록 실행 소유권을 명시한다. 장부가 바뀐 이후에는 코드만 이전 버전으로 되돌리지 않는다. 주문 중단·거래소 미해결 주문 대조·장부 호환성 확인을 포함한 복구 절차를 준비한다.

진행 상태를 갱신할 때 대상 파일·검증 증거·적용 프로세스·미완료 범위를 남긴다. 완료되지 않은 목표 폴더를 현재 실행 구조로 소개하지 않는다.
