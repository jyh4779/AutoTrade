# 시장별 정책

## 주식: 현재 운영

- 투자 대상은 코스피. KIS 거래량 순위 목표 100개, 부족하면 pykrx 거래대금 조회 보완, 실패 시 지정 코스피 대형주 목록을 사용한다. 실제 확보 수는 100보다 작을 수 있으며 REDUCED로 기록한다.
- 종목코드 끝자리 필터가 남아 있다. 상품 유형 마스터 기반 필터 전환은 미완료다.
- 코스피 대표 ETF `069500`의 당일 일봉 등락률을 시장 판단에 사용한다. -1% 미만이면 신규 매수를 막고, -0.5% 미만이면 약세로 분류한다. 공급자 장중 시각은 검증하지 못해 경고로 기록한다.
- 시장 차단 중에도 종목 평가·가상 배분을 진행한다. 실제 주문 직전 차단한다.
- 기본 종합 점수는 기술 55%, 뉴스 35%, 재무 10%. 실제 설정은 `data/strategy_config.json`과 `strategy_manager.py`를 확인한다. 동적 기준값은 `auto_trade_main.py`에 있으므로 설정 파일만으로 실제 임계값을 단정하지 않는다.
- 기술 점수는 `strategy_logic.py`의 가격 범위·거래량·모멘텀과 RSI·갭 등의 조건이다. MACD나 볼린저밴드가 실제 점수에 반영된다고 설명하지 않는다.
- 뉴스는 RSS와 로컬 Ollama 분석이다. 모델명과 캐시 정책은 `src/utils/llm_client.py`에서 확인한다.
- 재무 점수는 OpenDART 기반이다. 소스 미확보 시 중립 점수 처리와 미검증 기록이 있으므로 재무 데이터 확보 성공으로 간주하지 않는다.
- 위험 한도는 `risk_policy.py` 및 주문 직전 검사 코드를 확인한다. 현재 비용률과 손실 기준 자본은 가정이 포함되어 있으며 일반적인 순자산 기반 위험 모델로 설명하지 않는다.

## 코인: 목표 설계, 실거래 미구현

업비트 원화 현물로 대상이 확정됐으며 공개 REST 데이터와 단일 shadow 평가가 구현됐다. 현재 설정·실행·제한은 [업비트 지침](08-upbit.md)을 따른다. 아래 항목 중 인증·주문·연속 운영은 여전히 목표다.

- 첫 범위는 한 거래소의 원화 현물 시장을 후보로 한다. 거래소 확정 전 특정 API를 공통 계약에 고정하지 않는다.
- 거래대금·스프레드·호가 깊이·거래 이력·상품 상태로 목록을 구성한다.
- 24시간 운영을 위한 평가 주기·봉 구간·일일 위험 한도 기준 시각을 명시한다. 주식의 390분 거래량 추정이나 시초가 갭 조건을 그대로 적용하지 않는다.
- 코인 전용 점수·시장 필터·변동성·최대 보유 시간·비용 모델을 검증한다. 기업 재무 점수를 복제하거나 빠진 점수의 가중치를 임의로 이전하지 않는다.
- 기본 지표 계산은 공유할 수 있지만 매개변수와 전략 성과는 별도로 검증한다. 두 시장의 같은 점수를 동일한 기대수익으로 비교하지 않는다.
- 주문 규격·최소 금액·수수료·API 제한은 선택한 거래소의 공식 문서와 계정 조회로 확인한다. 거래소 연결의 권한과 실거래 활성화는 구분한다.
- 평가·모의·실거래 장부와 한도를 분리한다. 데이터 수집·주문 없는 검증을 완료한 뒤 실거래 적용 범위를 확인한다.
