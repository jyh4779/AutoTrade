# 업비트 원화 현물

## 현재 구현

2026-09-12: Ubuntu 이전 작업을 위해 Windows 코인 프로세스를 중단했다. 자동 재실행하지 않는다. `ML_CRYPTO_DATA`로 저장 경로를 주입하며 Linux 파일 잠금·SIGTERM 처리·5분 성과 집계를 추가했다. 현재 배포·이전 절차는 [서버 배포 문서](../deploy/crypto/README.md)를 따른다. 아래 Windows 실행 기록은 이전 운영 이력이다.

공개 REST API만 사용한다. 인증키·계좌·주문 API는 연결하지 않았다. `src/adapters/upbit/public.py`는 원화 목록·현재가·15분 봉·호가를 조회하고, `src/markets/crypto/strategy.py`는 순수 평가, `src/runners/crypto.py`는 주문 없는 실행을 담당한다.

```powershell
venv2\Scripts\python.exe -m src.runners.crypto
```

위 명령은 단일 실행이다. 연속 모의 실행은 아래 별도 실행기를 사용한다. 실행 모드는 shadow로 고정되어 외부 환경의 live 설정으로 주문이 활성화되지 않는다. 두 실행기는 같은 잠금을 사용하므로 동시에 실행하지 않는다.

```powershell
venv2\Scripts\python.exe -m src.runners.crypto_daemon
```

2026-09-11 연속 모의 실행 구현: 15분 구간마다 평가 작업을 별도 스레드에서 실행하고 약 15초 주기로 보유 및 최근 신호의 호가를 조회한다. API 처리 시간이 길면 관측 간격도 늘어난다. 시장 데이터 실패 시 신규 진입을 차단하고 기존 보유 청산 조회는 지속한다. 종료·재시작 시 DB에서 포지션·신호를 복원한다. 중단 중 가격을 소급 체결하지 않는다.

운영 상태는 `reports/daemon.json`, 감시 결과·모의 손익은 `reports/paper_latest.json`, 평가 상태는 `reports/evaluation_latest.json`, 시간 구간 비교는 `reports/feedback.json`이다(모두 `data/crypto/upbit/` 아래). PID와 UTC 최근 시각으로 실제 갱신 여부를 확인한다. RUNNING 기록만 남아 있어도 프로세스가 종료됐을 수 있다.

백그라운드 실행 로그는 `log/crypto_daemon.log`, `log/crypto_daemon_err.log`다. 현재 Windows 시작 시 자동 실행·장애 시 외부 재기동 서비스는 등록하지 않았다. PC 절전·재부팅 중에는 감시하지 못한다. `--once`는 신호 평가 없이 감시 한 번만 수행하는 점검 옵션이다.

REST 관측 사이의 가격 경로·주문 대기열·실제 부분 체결은 재현하지 않는다. 15초 감시를 연속 틱 검증으로 표시하지 않으며 모의 수익을 실거래 성과로 해석하지 않는다.

저장소는 `data/crypto/upbit/` 아래다. `data/audit.db`에 코인 이벤트·스냅샷을 저장하고 `reports/<run_id>.json`에 결과를 기록한다. 이 경로는 주식의 `data/audit.db`와 별개다. 주식 장부·잔고·설정은 읽거나 수정하지 않는다.

## 초기 연구 설정

원화 거래쌍 중 시장 경보가 없고 24시간 거래대금 10억원 이상인 거래쌍을 거래대금 순으로 최대 20개 선정한다. 시세 타임스탬프가 오래된 경우 제외한다. 모든 원화 거래쌍에 선정 또는 제외 사유를 보관한다.

확정된 연속 15분 봉 25개를 요구한다. 미확정 봉 제외, 누락 구간·오래된 봉·다른 상품 응답은 평가 불가 처리한다. 무거래로 봉이 생성되지 않은 경우도 임의로 가격을 채우지 않는다.

추세 40%, 1시간 모멘텀 40%, 상대 거래량 20%의 연구용 점수다. 기준 0.65, 최대 스프레드 0.2%, 양쪽 상위 5호가 중 작은 쪽의 잔량 금액 500만원을 초기 필터로 사용한다. BTC 1시간 수익률 -3% 미만 또는 데이터 실패이면 가상 후보의 진입을 차단하지만 종목 평가는 지속한다.

이 수치는 수익성이 입증된 매개변수가 아니다. 가상 후보는 체결·손익이나 예산 배분을 의미하지 않는다. 가격은 확정 봉 종가이며 실제 체결 가격이 아니다.

## 검증과 제한

### 2026-09-11 피드백 확장

- `experiments.py`는 기존 40/40/20 배점을 유지한 채 25/20/20/20/15 실험 배점을 병행 계산한다. 실험 기준은 0.70이며 실거래에 적용하지 않는다. BTC 수익률과 실험 설정도 입력 스냅샷에 저장한다.
- 선정 목록은 한 시간 내 이전 구성 중 상위 25위 안에 남은 종목을 우선 유지하며 최대 20개다. 경보·유동성 조건을 무시하지 않는다. 실제 모의 보유 종목은 선정 목록 밖에서도 별도 조회한다.
- 원화 현재가 관측을 누적하고 최근 7일 중 완전히 지난 UTC 일자의 마지막 관측값으로 거래대금 중앙값을 산출한다. 3일 미만이면 미확인이다. 이는 하루 거래대금의 정확한 일별 집계가 아닌 24시간 이동 거래대금 표본이며, 아직 진입 차단 기준으로 사용하지 않는다.
- `data/crypto/upbit/data/research.db`에 관찰·목록·신호·호가·모의 포지션·청산 결과·고정 기간 결과를 분리 저장한다. 기존 신호의 재실행은 전략/종목/확정 봉 식별자로 중복 진입을 막는다.
- 모의 포트폴리오는 전략별 초기 100만원, 건당 10만원, 최대 3개 보유, 편도 비용률 0.05% 가정이다. 실제 계정 수수료가 아니다. Decimal로 호가 잔량을 소진하며 수량·금액·비용을 계산한다.
- 신호 이후 다음 관측에서만 진입한다. 20분이 지난 신호, 시장 차단, 스프레드 초과, 잔량 부족은 진입하지 않는다. 진입 순서는 실행기의 관측 순서이며 최고 점수 우선 최적 배분은 아니다.
- 모의 청산은 후속 관측 호가에서 -3%/+5% 또는 1시간 경과 시 적용한다. 실행 사이 가격 경로를 관측하지 않으므로 봉 내부 손절·익절이나 최대 상승·하락폭을 검증한 결과가 아니다. 실행이 멈추면 자동 청산도 수행되지 않는다.
- 상세 평가 종목의 매수/미매수 신호는 60~75분 후 관측된 매도 호가와 신호 시점 매수 호가를 비교한 비용 반영 결과를 별도로 만든다. 포트폴리오 손익과 구분하며 해당 구간의 자료가 없으면 미확정으로 유지한다. 상세 평가하지 않은 전체 원화 거래쌍의 가상 손익은 아직 생성하지 않는다.
- 피드백은 아래 읽기 전용 명령으로 생성한다. 신호/결과 시각이 학습·검증 경계를 넘는 표본을 제외하고 15분 간격을 둔다. 아직 표본 부족이며 배점 선택·승격을 자동 수행하지 않는다.

```powershell
venv2\Scripts\python.exe -m src.reporting.crypto_feedback
```

보고서: `data/crypto/upbit/reports/feedback.json`. 점수 구간별 평균과 건수, 확정·미확정 신호 수는 각 평가 보고서의 feedback에 포함한다.

후속 검증: 정확한 다일 거래대금·상장 이력, 전체 비교군 가격 경로, 최대 낙폭·회전율·코인별 집중도, 지표 제거 실험과 반복 외부 기간 검증. 현재 구현만으로 전체 성과 검증 계획이 완료된 것은 아니다.

실행 결과에는 전체·선정 종목 수, 점수, 탈락·오류 사유, 시장 판단, 주문 수 0을 기록한다. 입력 스냅샷으로 같은 평가를 재실행하고 가중합을 별도 확인한다. 이는 전부 독립적인 전략 검증이나 백테스트가 아니다. PASS는 평가 가능, UNKNOWN은 데이터 부족, FAIL은 재현 불일치다. 종료 코드는 각각 0/3/2다.

공개 API 요청은 순차 간격을 두고 타임아웃·연결 오류만 제한 재시도한다. 429·418에서는 즉시 오류로 남긴다. 연속 호출 서비스, WebSocket 연결 복구, 장기간 분봉 수집, 과거 재현 CLI, 모의 체결·손익 원장, 인증 계좌·실주문·정밀 주문 규격은 후속 구현 범위다.
