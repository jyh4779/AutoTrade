# 모멘텀·실험 전략 실행 조건 비교

2026-09-15 후속 변경: 현재 배분은 [100만원·점수 구간별 투자 기준](12-live-setup.md)을 따른다. 아래 고정 10만원 조건은 comparison_v1의 과거 조건이다. 일일 손실 한도는 적용하지 않으며 아래 잔여 항목의 일일 손실 제한 요구를 대체한다.

## 구현과 운영 범위

2026-09-15: `comparison.db`에 두 전략의 새 모의 장부를 만들었다. 기존 `research.db`는 기존 체결 모형과 과거 성과를 보존한다. 새 장부의 수익률을 과거 장부의 누적 수익률과 섞지 않는다.

- 기존 모멘텀 모의매매와 실험 전략 모의매매는 같은 관측 호가 ID, 초기자금, 매수금액, 보유 한도, 수수료와 지연 설정을 사용한다.
- 기본 가정: 초기자금 각 100만원, 주문 10만원, 최대 3종목, 최소 주문 5천원, 매수·매도 수수료 각 0.05%, 최소 지연 1초. 실제 계정 수수료 확인값이 아니다.
- 신호 이후 주문 의도를 저장하고, 다음 유효 호가에서 체결한다. 15초 표본 주기 때문에 실제 모의 지연은 1초보다 길 수 있다.
- 관측 호가 잔량만큼 부분 체결 후 나머지를 취소하는 IOC 근사 모형이다. 매도 잔량은 포지션에 남기고 다음 관측에서 청산 조건을 다시 판단한다. 최소 주문 미만 잔량은 자동 청산하지 않는다.
- 실험 전략의 주문은 실거래 주문 경계에서 거부한다. 실거래 키를 모의 데몬에서 읽거나 인증 API를 호출하지 않는다.
- 요청 속도는 프로세스 내 공개 API 인스턴스가 공유하는 0.22초 간격 제한을 사용한다. 같은 IP의 다른 프로세스·외부 서비스 호출까지 통제하지는 않는다.

## 파일과 진단

- `/var/lib/ml-crypto/data/comparison.db`: 신호, 의도, 체결, 포지션, 청산, 관측 ID, 조건 버전.
- `/var/lib/ml-crypto/reports/comparison_latest.json`: 두 모의 전략 성과·보유·미처리 주문, 실거래 비활성 상태. 5분 집계.
- `/var/lib/ml-crypto/data/comparison_profile.json`: 선택적 가정 설정. DB 생성 후 조건 변경은 거부한다. 새로운 조건은 새 장부로 시작해야 한다.
- 실제 호가 원문은 같은 관측 시각·종목의 기존 연구 장부에 저장된다. 호가 정리 정책 구현 시 비교 체결에 연결된 원본도 보호해야 한다.

## 실거래: 아직 활성화 불가

인증 어댑터와 별도 `LiveOrders` 주문 저장·조회 대조 구성요소를 추가했다. 고유 identifier를 저장한 뒤 제출하며, 응답 유실 시 UNKNOWN으로 남긴다. 재시작 후 동일 의도는 다시 제출하지 않고 조회한다. 부분 체결·취소 결과의 누적 수량과 실제 수수료를 원장에 저장한다.

이는 실거래 자동운영 완성을 의미하지 않는다. 운영 데몬에는 연결하지 않았다. 사용자 투자 한도와 API 설정 확정 후 아래 작업을 완료해야 한다.

1. 계정별 실제 수수료·최소 주문·잔고를 확인하고 공통 조건에 반영.
2. 총 투자금·일일 손실 한도, 실제 포지션 및 부분 체결 원장 대조, 잔고 불일치 차단 구현·검증.
3. 실거래 모멘텀 실행기와 긴급 중단·청산 절차 연결.
4. 동일 신호의 실체결과 모멘텀 모의체결을 연결한 지연·가격·수수료 오차 보고.

키·투자 한도가 없는 상태에서 `enabled=True`를 사용하거나 주문 구성요소를 수동 실행하지 않는다. 현재 보고서의 live=DISABLED는 실제 주문이 없음을 명시한다. 외부 대기열·시장 충격·실제 계정 수수료는 검증 전이므로 모의 환경을 실거래와 동일하다고 표현하지 않는다.
