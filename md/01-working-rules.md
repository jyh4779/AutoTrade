# 공통 작업 규칙

## 환경과 소통

- 답변과 운영 보고서는 한국어로 작성한다.
- 작업 루트는 `D:\ML`, Windows PowerShell, Python 3.12 계열 `venv2\Scripts\python.exe`를 사용한다.
- 현재 루트에 의존성 명세가 없다. 환경 변경 시 설치 내용과 재현 방법을 기록한다. 기존 가상환경을 임의로 재구성하지 않는다.
- 비밀키·토큰·계좌번호를 로그·문서·테스트 결과에 출력하지 않는다. 인증 파일 전체를 확인용 출력에 포함하지 않는다.

## 작업 범위

- 사용자 요청과 이미 승인된 범위 안에서 읽기·수정·검증을 진행한다. 같은 권한을 반복 요청하지 않는다.
- 검증 목적으로 실주문을 실행하지 않는다. 주문 없는 평가 또는 격리된 가짜 브로커를 사용한다. 실제 매매 실행은 해당 실행까지 승인된 범위에서만 수행한다.
- 구조 개편과 전략 변경을 분리한다. 구조 변경에서 배점·매수 기준·손절 값을 함께 바꾸지 않는다.
- 기존 사용자 변경을 보존한다. 코드·설정·장부 변경의 차이를 구분해 보고한다.
- 장부 스키마를 바꾸기 전 백업과 전환·복구 방법을 준비한다. 실행 중인 DB를 단순 파일 복사해 일관된 백업으로 간주하지 않는다.

## 구현 원칙

- 공통 계층에 KIS 또는 특정 코인 거래소 API를 직접 호출하는 코드를 넣지 않는다.
- 시장별 규칙을 공통 엔진의 반복적인 시장명 분기로 구현하지 않는다. 정책 또는 연결 인터페이스로 주입한다.
- 수신 시각을 거래소 발생 시각으로 표시하지 않는다. 누락된 데이터를 정상값으로 채워 판단 근거를 만들지 않는다.
- 주문 응답 유실은 미체결 확정이 아니다. 조회·대조로 상태를 해소하며 새 주문을 무조건 재전송하지 않는다.
- 실험 모델, 모의 결과, 실제 체결을 명확히 구분한다. `models/` 및 `src/models/`의 기존 ML 실험을 현재 매매 점수의 근거로 설명하지 않는다.

테스트와 완료 판정은 [검증 지침](06-validation.md)을 따른다.
